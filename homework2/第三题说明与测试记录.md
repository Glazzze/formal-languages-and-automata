# 第三题：受限堆栈判定、边界测试与跨题独立验证

## 一、判定目标与算法

判定语言 `L = {0^k 1^k | k >= 1}`。`question3_stack_membership.py` 中的 `judge(s)` 用列表 `S` 作显式堆栈：

1. 读入前导 `0` 时压入 `"0"`；若栈顶已是阶段标记 `"|"`，说明 `0` 出现在 `1` 之后，立即拒绝。
2. 读到第一个 `1` 时压入阶段标记 `"|"`，同时弹出一个 `"0"`。
3. 之后每读一个 `1`，先弹出标记、再弹出一个 `"0"`，再把标记压回；若此时栈为空说明 `1` 多于 `0`，拒绝。
4. 标记在栈顶时，弹出标记后若栈为空，说明全部 `0` 已匹配，多读的 `1` 应拒绝。
5. 其它字符直接拒绝。输入结束时只有栈恰为 `["|"]` 才接受。

因此空串、缺少 `1`、数量不等、`1` 之后又出现 `0` 以及非 `0/1` 字符都被拒绝。

## 二、变量审查

`judge` 的显式参数只有 `s`，函数体内只有堆栈 `S` 和 `for` 循环变量 `ch`，没有计数器、阶段标志、结果变量、辅助列表或递归。阶段信息存放在堆栈标记 `"|"` 中，尚未匹配的个数由栈内 `"0"` 的个数表示。

`verify_submission.py` 的自动审查直接读取函数对象的局部变量表与全局引用表，实测输出：

```text
局部变量：['S', 'ch', 's']；仅参数 s、堆栈 S、循环变量 ch
未发现递归调用
```

`verify_submission.py` 本身是测试脚本，不属于受限判定核心，其测试数据与统计变量不受题面限制。

| 检查 | 方法 | 实际结果 |

合并关系（供与第二题实际输出对照）：

| 原状态 | 最小化状态 |
| --- | --- |

| 标记 | 状态 | 对应原状态 | 0 | 1 |

说明：C 的最小化状态命名为 `Q0/Q1/Q2`，与本文档的 `X/Y/Z` 只是命名差异；核验比较的是状态分组（集合的集合）而非名字。短串核验只用于查错，不替代乘积自动机/状态对算法本身的通用性结论。
